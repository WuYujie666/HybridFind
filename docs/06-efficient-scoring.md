这个课件主要讲的是 **“高效排序（Efficient Scoring）”**，核心目标就一句话：

> **如何在不明显降低检索质量的前提下，少算很多文档分数，快速找出 Top K 结果。** 

因为实际搜索系统里，**打分（score computation）占了大量 CPU 时间**，而且查询延迟通常只有几百毫秒预算，所以不能把所有文档都算一遍。

------

# 一、课件主线：为什么要“高效打分”

先从最核心的问题开始：

我们在向量空间模型里，本来是要算：

score(q,d)=cos⁡(q,d)

也就是 query 和 document 的余弦相似度。

但问题是：

- 文档总数 N 很大
- 真正有希望进前 K 的文档很少
- 全量计算太慢

所以本章研究：

> **如何尽量只给“可能进入 Top K”的文档打分。** 

------

# 二、Top K 不需要全排序

课件先讲了一个很重要的思想：

我们通常只关心 **前 K 个结果**，不需要把所有文档完整排序。

所以可以用：

- **Heap（堆）**
- 不做全排序，只维护前 K

这样复杂度会小很多。

这个思想你前面学过 TF-IDF 排序时已经见过了：

> 给每篇文档一个 score，按 score 排序
>  其实真正做的是 **只保留最大的 K 个分数**

------

# 三、本章最核心：Pruning（剪枝）

这一章真正重点是：

> **剪掉不可能进入 Top K 的文档**

课件把它叫：

> **Speeding cosine computation by pruning** 

------

## 1）Index Elimination（索引消除）

最经典的一种优化。

------

### 方法 A：只看高 idf 词

比如查询：

> catcher in the rye

真正重要的是：

- catcher
- rye

像：

- in
- the

这些停用词 idf 很低，对排序贡献小。

所以可以直接忽略。

这本质就是：

> **优先保留信息量大的 query term**

------

### 方法 B：只算包含多个 query term 的文档

比如 4 个词查询，只算至少包含 3 个词的文档。

这是搜索引擎里很经典的：

> **soft conjunction（软 AND）**

例如：

> 4 个词里命中 3 个就算候选

这样能砍掉大量无关文档。

------

# 四、Champion List（重点高频考点）

这是考试非常爱出的。

思想是：

> 对每个 term，提前保存最重要的 r 个文档

即：

> **这个词最“代表性”的前 r 个文档**

查询时只在这些文档里算分。

你可以理解成：

> 每个词提前准备一个“精英候选名单”

这样速度很快。

------

# 五、加入静态质量分（非常重要）

这一部分特别像现代搜索排序。

课件说：

文档不仅要 **relevant（相关）**，还要 **authoritative（权威）**。

于是加入一个和 query 无关的质量分：

g(d)

例如：

- PageRank
- 引用数
- 网站权威性
- 点赞收藏量

最后总分：

net-score(q,d)=g(d)+cos⁡(q,d)



这就是现代搜索排序最基本思想：

> **相关性 + 权威性**

------

# 六、Cluster Pruning（聚类剪枝）

这一块是非常经典的近似检索思想。

流程是：

1. 随机选 \sqrt{N} 个 leader
2. 每篇文档挂到最近 leader
3. 查询时先找最近 leader
4. 只搜索这个 leader 的 followers 

核心思想：

> **先缩小搜索范围，再精排**

这和现代 ANN / 向量数据库思想非常像。

------

# 七、Tiered Index（分层索引，考试重点）

这是这章另一个超级重点。

把倒排索引分层：

- Tier 1：最重要
- Tier 2：次重要
- Tier 3：普通

查询时：

> 先搜高层，不够 K 个再往下搜。 

这是现实系统非常常见的工程优化。

你可以理解为：

> **先看精品区，再看普通区**

------

# 八、WAND（本章最核心算法）

这一章最重要的算法几乎就是 **WAND**。

核心思想：

> 给每个 term 一个最大可能贡献上界 UB

如果某文档即使把所有剩余最大值加起来，仍然不可能超过当前 Top K 最低分 threshold，

那它直接剪掉。

即：

> **没希望超过门槛的文档，连完整分数都不算**

课件实验结论：

> **90%+ 的 score computation 都可以省掉** 

这是工业界非常重要的 Top-K 检索算法。

------

# 九、最后：完整搜索系统怎么落地

最后一页是全流程架构图，很重要。

整个流程是：

> 用户 query
>  → query parser
>  → 拼写纠错
>  → 倒排索引 / 分层索引
>  → scoring and ranking
>  → results

你会发现：

这章本质上讲的是 **排序层的系统优化问题**。

------

# 一句话总结整章

这章可以浓缩成一句话：

> **用各种 pruning 技术，只给“有机会进入 Top K”的文档打分。**

核心方法包括：

- index elimination
- champion list
- static quality
- cluster pruning
- tiered index
- WAND
